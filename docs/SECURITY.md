# Hikari Protocol — Security Policy & Disclosure

> **Security Standards, Non-Custodial Safeguards & Vulnerability Disclosure Guidelines**
> Explains the security boundaries of Soroban contracts, keeper operations, key handling, and audit readiness.

---

## 1. Reporting a Vulnerability

Please **do not** open public GitHub issues for security vulnerabilities. Send reports privately:
- **Primary Contact**: Open a [GitHub Security Advisory](https://github.com/ibochivincent-lang/hikari/security/advisories/new).
- **Email**: `vincentibochi@gmail.com` / `ibochivincent-lang@users.noreply.github.com`.
- **Response Window**: Initial response within 24 hours; triage and remediation timeline within 72 hours.

Responsible security researchers are eligible for rewards under the Hikari Bug Bounty Program and will be credited in our public release notes.

## 2. Supported Versions

The `main` branch is the canonical production release surface on Stellar Mainnet / Testnet (Protocol 27).

---

## 3. Custody Boundary & Non-Custodial Architecture

Hikari is architecturally non-custodial:
- **Zero Private Key Access**: Neither the web interface, SDK, nor backend API ever requests, stores, or handles user private keys.
- **Client-Side Signatures**: All staking, wrapping, and unbonding transactions are signed client-side by user-authorized wallets (Freighter, Lobstr, xBull).
- **Smart Contract Execution**: Asset movements are governed strictly by open-source Soroban smart contract logic deployed on the Stellar ledger.
- **No Custodial Middlemen**: There are no admin keys capable of arbitrary user balance seizure.

See [`docs/NON_CUSTODY.md`](NON_CUSTODY.md) for full architectural proofs.

---

## 4. Key & Secret Management

- **User Wallet Keys**: Strictly retained in the user's browser extension or hardware wallet.
- **Keeper Daemon Keys**: Used solely to pay Stellar transaction gas for autonomous rebalancing, yield harvesting, and MEV backrunning. Keepers have zero authorization to transfer user principal.
- **GateSeal Ephemeral Pause Key**: A time-locked, single-use emergency pause key restricted to triggering Bunker Mode during catastrophic market anomalies. Cannot withdraw funds.
- **Session Authentication**: Nonces and challenge tokens generated by the backend use 32-byte cryptographic entropy with mandatory expiration to prevent replay attacks.

---

## 5. Invariant Verification & Supply Chain Security

- **Invariant Fuzzing**: Continuous 10,000-iteration property-based fuzz tests verify mathematical solvency ($R_t \ge S_t \times P_t$) on every commit.
- **Automated CI Scans**: CodeQL (`.github/workflows/codeql.yml`) and Dependabot (`.github/dependabot.yml`) scan for dependency vulnerabilities weekly.
- **Anti-Mixup Database**: Backend databases enforce strict public key tenant isolation, ensuring zero cross-session state contamination.
